CharonDOS application catalog - test record
============================================

Test date: 2026-11-20.  Data file: src/efi/CharonDosCatalog.h (generated).

Candidates looked at: 101.  Passed and offered: 38 (kPrograms).  Work alone but
blocked by emulator gap E1: 12 (kBlockedByStdHandleBug).  Rejected: 51 (kRejected).

How it was tested
-----------------
* Sources: the FreeDOS 1.4 package repository on ibiblio
  (https://www.ibiblio.org/pub/micro/pc-stuff/freedos/files/repositories/1.4/<group>/<name>.zip), two older
  FreeDOS packages (1.1, 1.2) and DOS Frotz 2.55 from the IF Archive.
* Emulator: src/dos of this tree as of 2026-11-20, built for the host with the
  flags of tools/build-charondos.py --host-only. The released
  charondos-r400/charondos-host.exe is older than bios.cpp / dosint.cpp /
  backend_host.cpp and was not the test subject. The test binary used a copy of
  backend_host.cpp with three additions to the key script only: {WAIT} (400 ms
  pause, needed because programs flush type-ahead when they start), {A-x} and
  {C-x}. No emulator source file was changed.
* The downloaded programs were never run on the host; they ran only inside the
  emulator. Each test got a fresh drive C: holding the program's files at the
  catalog's install path and C:\WORK with small text files and a two-level
  directory tree.
* Each program was started from the CharonDOS shell with scripted keys and had
  to do one real thing (see the table). Effects on files were checked on the
  host file system. After the program the script typed ECHO to prove that the
  shell and its console output were still alive. All interrupts that reach the
  emulator were logged (--inttrace) and calls the emulator does not implement
  were listed.
* Full-screen programs were judged from the final text screen (B800:0000).
* Not done: nothing was run on CHARONDOS.EFI / real UEFI, nothing was heard
  through the screen reader, and no program was used for longer than the
  scripted minute. "Passed" means the listed operation worked, not that every
  function of the program does.

Work alone, blocked by gap E1 (kBlockedByStdHandleBug)
------------------------------------------------------
Each of these did its job in a fresh session, then closed DOS handles 0, 1 and 2
(or only 0, where noted) on exit, as the Borland / Microsoft C run-time does.
After that ECHO and DIR of the shell print nothing, later programs cannot read
the keyboard through handle 0, and the next file a program opens can receive
handle 1, so console messages land in data files (seen with ZOO).

Emulator gaps met, in the order worth fixing
--------------------------------------------
E1  One handle table for all processes. A child that closes handle 0, 1 or 2
    (normal C run-time exit) closes it for the shell and for every later
    program. Fix: a job file table per PSP (inherit on EXEC, drop on
    terminate), or at least restore handles 0-4 of the parent when a child
    ends. Unblocks 12 tested programs at once: EDIT, OSPEDIT, HEXED, MORE,
    LESS, HEAD, FC, REPLACE, XGREP, B64, ZOO and Frotz (text adventures).
E2  Alt+letter in full-screen programs. The Alt bit of 0040:0017 appears
    together with the key and is cleared 400 ms later; FreeDOS EDIT (DFlat+)
    takes that as "Alt pressed and released" and closes the menu it has just
    opened. Seen with scripted keys on the host backend; F10 works. The Alt
    bit should be visible before the key and go away with the next non-Alt key.
E3  FreeDOS EDIT: F1 does not open the help window (EDIT.HLP is installed and
    opened at start; after F1 only an INT 21h AH=4Ah follows). Not analysed.
E4  INT 21h AX=4B01h (load without executing), AH=55h (create child PSP) and
    AH=5Dh. Without them DEBUG's G ends DEBUG and Insight cannot load a
    program.
E5  No ANSI escape sequences on the console (no ANSI.SYS). VITETRIS and the
    full-screen GNUCHESS.EXE print raw "ESC[" text.
E6  INT 21h AH=11h/12h (FCB find first/next) return FFh. ZDIR lists nothing.
E7  File name handling seen with GZIP: output "long.txz" ended on the host as
    LONG.TX and could not be opened again. Not analysed; worth a test with
    names whose extension is rewritten by the program.
E8  INT 10h AH=FEh (TopView video buffer) is ignored; Freemacs depends on it.
E9  No INT 33h mouse (AX=0 returns "not installed"). Correct for a keyboard
    system, but SUDOKU86 refuses to start. EDIT, Frotz and Doszip poll it
    constantly without harm.
E10 Graphics modes (04h, 13h) are not there by design: HANGMAN, DRMIND,
    PSR Invaders.
E11 80386 instructions (prefix 66h, opcodes 0Fh xx) are not there by design:
    TDE (TDER.EXE), SAYSWHO; every DJGPP / DOS/4GW program (16-bit UNZIP does
    not exist in the FreeDOS repository, so there is no stand-alone unzip in
    the catalog; Doszip and ZIP16 are the ZIP tools that work).
E12 Asked for and answered "not supported" without harm: INT 21h AH=71h/73h
    (LFN, FAT32), AX=440Dh, AX=4452h, INT 2Fh AX=4300h/1600h/2701h/4010h,
    INT 15h AH=E8h/C0h, INT 10h AH=1Bh/4Fh/EFh/0Bh.
E13 Programs without a hint: MSA ("No output file."), WHICH and FDBANNER
    (no output), ZMIY and DOS Navigator (hang).

Notes for the downloader
------------------------
* File names inside the ZIPs are case-sensitive and mixed (BIN/amb.com,
  appinfo/BSUM.LSM); File::zipPath is exact, File::dest is the 8.3 target.
* GNU Chess needs its data in the subdirectory MISC; this is why File has a
  separate dest.
* ELIZA and GNU Chess look for their data in the current directory: start
  `run` in installDir.
* fdhelp is data only and installs into the directory of ambread.
* Frotz needs story files (.z3/.z5/.z8), which are single files and not ZIPs;
  the catalog format has no entry kind for them yet.
* Logs of every run: work/dos-catalog/logs/<name>.log (outside this tree).
