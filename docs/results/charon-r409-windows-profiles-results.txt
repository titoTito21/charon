5. Network of the installed Windows
-----------------------------------
How Charon connects (READ, CharonWsNet.h): DHCP only; Wi-Fi WPA2-PSK or open through the firmware's
supplicant; no static address, DNS or proxy of its own; the password was wiped right after use. Now the
joined network (name, password) is kept in memory (net::Joined, used by the Linux side as well) and for
Windows written as \charon\network.conf on the install media (the same NAME=value text as for Linux,
NetworkConfNow). It is not under \EFI\HAK (CharonPrivate.h lists network.conf as never copied anyway) and
NOT in the answer file, so it does not reach Setup's cached copy in Windows\Panther. The answer file only
gets, right after the copy command: Charon-Network.ps1 -Language pl|en (HOST: vector windows-wifi-network; no
name or password in the file).
Charon-Network.ps1 (new): reads the file, deletes it (overwritten first; also the copy on the media when it
is writable), builds a WLAN profile of Microsoft's WLAN_profile v1 schema (WPA2PSK/AES with passPhrase or
64-digit networkKey, or open; connectionMode auto), "netsh wlan add profile filename=... user=all", deletes
the XML, "netsh wlan connect", waits up to 120 s for http://www.msftconnecttest.com/connecttest.txt and says
the outcome. 802.1X: refused with a spoken message, exit 2 (Charon itself cannot join such a network).
Documentation used: learn.microsoft.com/windows/win32/nativewifi/wlan-profileschema-schema ,
.../wpa2-personal-profile-sample , .../wlan-profileschema-sharedkey-security-element ,
learn.microsoft.com/windows-server/networking/technologies/netsh/netsh-wlan ,
learn.microsoft.com/powershell/module/nettcpip/new-netipaddress , .../dnsclient/set-dnsclientserveraddress .
Which pass: first logon. WinPE has no WLAN service, so nothing during Setup can use Wi-Fi; Charon's
installation needs no network before the first logon (NVDA and Charon's files are on the media). Profiles
and reader downloads now wait for the connection: up to five minutes, announced at the start and every
minute (Wait-Internet in the profile script, Wait-Network in Charon-Readers.ps1), then three tries as before.
RAN (Windows Server 2025 machine, which has the WLAN service but no radio; evidence\server\network-test.txt):
  - the generated profiles (passphrase with & and <, open, 64-hex key) are VALID against Windows' own
    schema files (%SystemRoot%\L2Schemas\WLAN_profile_v1..v5.xsd); a profile with a wrong authentication
    value is rejected by the same check ("The Enumeration constraint failed");
  - "netsh wlan add profile" itself cannot be exercised without a radio: "There is no wireless interface on
    the system." (exit 1, WlanSvc running). So the import and the connection are NOT verified;
  - network.conf from the media, no Wi-Fi adapter: file deleted, the password is in no log, spoken message
    "Windows has no driver for this computer's Wi-Fi adapter ... I did not keep the network password", exit 3;
  - 802.1X refused, exit 2;
  - static address (the script's -Address/-Gateway/-Dns, by hand: Charon has none to pass): set on the
    Ethernet adapter, DHCP off, online check true, then put back to DHCP.
Ethernet with DHCP: every trial machine was installed and downloaded that way.
Not done: Wi-Fi driver injection; a proxy; a real Wi-Fi join; WPA3-only networks (Charon cannot join them).

6. Charon's voice for NVDA (voice.conf)
---------------------------------------
Charon-Readers.ps1 now reads %ProgramData%\Charon\voice.conf (CHARON_SYNTH, _VOICE, _RATE, _PITCH,
_PUNCTUATION) before NVDA is started. rhvoice: the engine add-on RHVoice-1.18.201.nvda-addon (release 1.18.2,
SHA-256 f15a127a...a7b9 = GitHub's digest) and the voice's add-on (addresses of src/synth/rhvoice/VOICES.tsv,
Charon's own SHA-256 of each of the ten files, in the script) are unpacked into NVDA's add-on folder, NVDA's
configuration gets synth RHVoice, the voice, rate, pitch (5..20 -> 25..100, 10 = 50) and the punctuation
level, and the same goes to NVDA's sign-in-screen configuration. A voice without an NVDA add-on (Dasha,
Evgeniy, Lyubov) is replaced by the first voice of its language, a failed download by another voice of the
language, else NVDA keeps its own synthesizer; each case is spoken and logged. espeak: NVDA's eSpeak NG.
RAN (Server 2025 machine, NVDA 2026.3; evidence\server\rhvoice): natan (Polish) and slt (English): NVDA's
log "Loaded synthDriver RHVoice", configuration as written, sound measured; lyubov -> announced, Slt used;
espeak -> "Loaded synthDriver espeak". Found and fixed on the way: NVDA must be stopped before its add-ons
are replaced. Not done: RHVoice for Narrator/SAPI 5 (the voice installers' silent mode is not documented and
was not tried; Narrator keeps its Windows voice, logged); the sign-in screen with RHVoice was not listened to;
whether Charon's EFI side writes voice.conf for Windows was not run here.
