Code changed
------------
Sound drivers (UEFI):
- src/efi/CharonUsbAudio.h, tests/CharonUsbAudioTests.cpp, CharonAudioDevice.h, CharonVoiceProvider.h:
  the USB Audio Class output written the day before in work/charon-src-usbaudio merged into this tree.
- src/efi/CharonEs1371.h (new), tests/CharonEs1371Tests.cpp (new), CharonAudioDevice.h (7 lines marked
  r406): own driver for Ensoniq ES1371/ES1373 (VMware's default card): DAC2, 48 kHz stereo 16-bit, polled
  DMA, no interrupts; opened after AC'97. VMware's model hands over one period and waits until the serial
  register is rewritten, so the driver rewrites it at every 10 ms service (2048-frame period).
- src/efi/audio_stream/driver/HakHdaCompat.h, HakHdaCompat.c, HakHdaCodecCompat.c (new),
  apply-driver-extension.py, BUILD-NOTES.md, audio_stream/AUDIO-HARDWARE.txt (new): AudioDxe-r406 for
  newer laptops: binds Intel class 04/01 and 04/80 controllers only with a memory BAR0, a sane HDA
  register block and an answering codec; 1 ms in reset, Skylake+ clock gating off during reset, ATI/AMD/
  NVIDIA snoop bits; codec D0 waited for, EAPD on every capable pin, headphone amp bit, Realtek amplifier
  GPIO by codec subsystem ID. Driver: work/charon-audio-driver-r406/AudioDxe-r406.efi (+ -trace).
- CharonAc97.h: DisconnectFirmwareHda also covers Intel 04/01 and 04/80 with a memory BAR0.
- CharonVoiceProvider.h: a device that stopped with an error other than a timeout is restarted (at most
  8 times, maximumFaultRestarts) - after speech stopped in the installer dialogue, see trial 4.
- CharonAc97.h, CharonVoiceProvider.h, CharonAudioDevice.h, HAKBootEFI.cpp, CharonResident.h
  (work/edit-hdadrv-r406.py, edit-drvtrace-r406.py, edit-hdatpl-r406.py): the sound card is taken over
  from a firmware HD Audio driver only at TPL_APPLICATION; above it nothing is disconnected and a
  controller held by a firmware driver is not connected; the reader driver does both when firmware starts
  a boot option (its StartImage hook). Trace lines "CHARON driver: ..." added. Reason: trial 14.

Linux installs, desktops, screen readers, progress sounds:
- src/linux/ (new folder): speech.sh, live-speech.sh, install-charon.sh (texts taken out of the C headers
  with work/render-cstring.py), progress.sh, firstboot.sh, charon-tone.c (new); tools/
  gen-charon-linux-scripts.py writes src/efi/CharonLinuxScripts.h from them (round trip checked, sh -n
  PASS for all five); tools/build-charon-tone.py; CharonWsInstall.h, CharonWsInstall2.h,
  CharonWsInstall3.h wired to them (work/edit-install-r406.py).
- charon-tone.c + progress.sh: progress tones as NVDA's progress bar (110 Hz at 0 percent, higher with
  progress, 40 ms), from a static program without a C library, so they sound before any sound package is
  installed; used by the first start of ready images (firstboot.sh), by the Debian installer (preseed
  early_command "progress.sh watch /target") and by the Ubuntu installer script (live-speech.sh).
- firstboot.sh (new) replaces the package list given to cloud-init: speech first, then the desktop, with
  tones and a log in /var/lib/charon/firstboot.log; downloads are retried, speech is announced only
  when it is there (work/edit-retry-r406.py).
- speech.sh: speaking sign-in screen (GDM, LightDM; mute SDDM replaced), accessibility switched on for
  GTK/Qt programs, Orca's speech language; console reader and desktop share the sound card
  (charon-audio-share): no step waits (Fenrir's stop had hung a session start), TimeoutStopSec=3; system
  services play straight to the card (ALSA default = plug:sysdefault) because the PipeWire default
  refused root ("Host is down"); on a system without a sound server no reader is stopped.
- Sign-in mode asked in the dialogue: graphical, or console with startx (work/edit-login-r406.py;
  speech.sh, firstboot.sh, CharonWsReaders.h, answer files).
- progress.sh charon_tls_check: when HTTPS with the large TLS 1.3 greeting gets no answer but the classic
  key exchange does, OPENSSL_CONF in /etc/environment selects the classic one (found in trial 6);
  pacman run with LC_ALL=C.
- install-charon.sh + HAKBootEFI.cpp (work/edit-register-r406.py): the reader add-on sets a volatile
  variable CharonVoiceLoaded; "charon-register check" at every start of the installed system: when
  firmware did not load the add-on, the marker \EFI\HAK\reader-only is written and the entry Charon goes
  first in BootOrder (Charon then speaks and goes straight on to the system).
- CharonWsInstall.h, CharonWsCore.h (work/edit-hakboot-r406.py): Charon started from its boot disc is
  \EFI\BOOT\BOOTX64.EFI and has no \EFI\HAK\HAKBOOT.EFI; the installed copy now gets the running program
  under that name (the boot entry "Charon" had no target); space reserved for it 8 -> 40 MB.
- BootMenu.h (work/edit-shortform-r406.py): Charon resolves short-form boot options (HD(partition)/File,
  as efibootmgr writes them) itself; LoadImage did not expand them (trial 7).
- BootMenu.h (work/edit-greet-r406.py): in reader-only mode time is left for the greeting "Charon."
  before the system is started.
- CharonWsInstall.h: the tone watcher started by the Debian preseed closes descriptors 3-6; it had kept
  debconf's channel open and the installer waited for ever (trial 8).

Windows:
- tools/charon-addon/Charon-Readers.ps1 (work/edit-readers-ps-r406.py and hand edits): NVDA 2026 is a
  64-bit program in Program Files (older ones in Program Files (x86)), winget installer x64, start-at-
  sign-in token nvda_nvda_v1.
- CharonWsInstall2.h: the check "exactly one internal disk" for the automatic Windows install runs
  before the questions, not after them (trial 11); Windows Setup always speaks with Narrator, NVDA on
  the media is only installed at first logon (work/edit-nvdasetup-r406.py; trial 11); an edit for media
  that hold two Windows images (Setup stopped at the edition question in trial 11).

CharonDOS / CharonPC:
- CharonWsDosSystem.h, CharonWsDisks.h (work/edit-disc-r406.py): Windows profiles take the user's own
  disc in a CD/DVD drive; it is read whole into the profile as SETUP.ISO.
- src/pc/pc_config.cpp (work/edit-pccfg-r406.py): the emulator accepts the profile keys the installer
  writes (size of the empty disk to make, state = install | no-media | installed); it had refused them,
  which stopped every Windows profile. An installing profile boots "cdrom,disk".
- src/pc/pc_efi.cpp (work/edit-pclog-r406.py, edit-pcdiag3-r406.py): Bochs log mirrored to COM1 and
  written to disk every two seconds; the console mode is no longer switched when it already is 80x25.
- src/pc/pc_gui.cc (work/edit-pcdiag*.py, edit-pccursor-r406.py, edit-pcmenu-r406.py): a state line
  every 5 s in the log; firmware cursor hidden while cells are written; the start menu of a Windows 98 /
  ME disc ("1. Boot from Hard Disk  2. Boot from CD-ROM") is answered with 2 by the emulator while the
  profile's disk holds no system (a boot sector alone does not count), with a spoken message.
