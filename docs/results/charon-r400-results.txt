Charon r400 - wyniki prób (2026-11-19, QEMU 11.1 + OVMF, Windows host)
======================================================================

Buildy: work/charon-win-r400 (CHARON.EFI, bez śledzenia), work/charon-win-r400-drv
(CHARONVOICE.EFI), próby na buildach śledzonych r400a..z z tych samych źródeł
(work/charon-src-r395). Sterownik dźwięku: charon-audio-driver-r400 (strumień rev 3).
Nic nie było sprawdzane na fizycznym sprzęcie.

1. Przegląd kodu: 23 poprawki (CharonResident.h, menu, LiveVoice, USB) - kompilacja
   -Wall -Wextra -Werror czysta; regresja menedżerów niżej.

2. Przestrzeń robocza (menu główne -> "Przestrzeń robocza"): nawigacja, skan programów
   *.efi, edytor (pisanie, zapis), pliki, paleta poleceń, kalkulator - ZALICZONE
   (charon-r396-menu.py, mowa w logu szeregowym).

3. Sieć: DHCP 10.0.2.15, pobranie pliku przez HTTP z hosta, ładowanie sterownika karty
   z \EFI\HAK\drivers (romfile= wyłączony) - ZALICZONE. Pobranie przez HTTPS własnym
   klientem (BearSSL) w firmware - ZALICZONE (r400t). Klient na hoście: 23/23 kontroli
   (tests/CharonHttpsHostTest.cpp), w tym odrzucenie złych certyfikatów.
   Wi-Fi: NIESPRAWDZONE (QEMU nie ma Wi-Fi).

4. Obraz płyty z pamięci: http://10.0.2.2:8765/mini.iso (Debian mini.iso) pobrany do
   RAM z paskiem i mową co 10%, zarejestrowany w EFI_RAM_DISK_PROTOCOL, uruchomiony;
   czytnik odczytał GRUB-a z płyty ("grub: menu, 2 pozycje. Install, 1 z 2") -
   ZALICZONE (maszyna t401, build r400v).

5. Instalacja Debiana z sieci (maszyna deb2, tryb szybki, pl, bez pulpitu, mowa tak):
   dialog -> jądro i initrd do RAM (pasek, mowa dziesiątek) -> całe \EFI\HAK dopisane
   jako cpio w RAM -> LoadFile/LoadFile2 -> d-i automatycznie z własną mową ->
   nowa ESP ma 61 plików Charona (HAKBOOT.EFI hash zgodny), Driver0000 "Charon voice",
   Boot "Charon" po "debian"; po restarcie firmware ładuje czytnik, czytnik czyta
   GRUB-a Debiana, system startuje, espeakup aktywny - ZALICZONE.
   Uwaga: OVMF z urządzeniem bootindex usuwa wpisy Boot spoza fw_cfg (artefakt QEMU).

6. Instalacja Windows 11 z sieci: NIESPRAWDZONA. Plik odpowiedzi i start Setup z
   nośnika - tylko kompilacja. Pobranie ISO od Microsoftu do RAM: klient dostał
   prawdziwy link na hoście raz, dwie kolejne próby 2026-11-19 odrzucone na etapie
   sesji (vlscppe, "could not connect"); start Windows Setup z dysku RAM nie był
   wykonany i może nie działać po przejęciu sterowania przez Windows.
   Ubuntu (autoinstall): napisane, NIESPRAWDZONE.

7. CharonDOS: testy hosta 33/33; pod UEFI uruchomiony jako pakiet, polecenia powłoki
   czytane przez czytnik - ZALICZONE. Programów MS-DOS firm trzecich nie uruchamiano.

8. Sterownik czytnika:
   - powitanie: dwa tony rosnące 784 -> 1175 Hz i "Charon." - ZALICZONE (nagranie);
   - pożegnanie przy ResetSystem (GRUB "reboot"): tony 1175 -> 784 Hz, potem
     "Wyłączanie Charona.", restart po 1,6 s; Enter -> tony 0,2 s - ZALICZONE
     (work/farewell-test.sh, farewell-check.py; nagranie deb2/live2.wav).
     GRUB "halt" wyłącza przez ACPI z pominięciem firmware - bez pożegnania (ograniczenie).
   - szybki rozruch bez podłączonej karty dźwiękowej: sterownik sam podłącza kartę;
     nieudane zatrzymanie dźwięku nie blokuje startu systemu - ZALICZONE;
   - "ha, ha, haron" (restart wypowiedzi po przestoju firmware) - naprawione, ZALICZONE;
   - ciche menu z odliczaniem (czytane dopiero po klawiszu), komunikaty rozruchu czytane -
     ZALICZONE na GRUB-ie Debiana w obu wariantach;
   - GRUB Debiana: zaznaczenie '*' zamiast całej ramki ("Debian GNU/Linux, 1 z 3") - ZALICZONE.

9. Dźwięk po ExitBootServices (Linger, strumień rev 3): PROBE.EFI, "CHARON linger=1",
   sygnał co 1,2 s po przejęciu sterowania - ZALICZONE.

10. Opis ekranów graficznych (kolory, kształty, logo, postęp): tests/CharonLogoProbe.cpp -
    ZALICZONE.

11. Regresja menedżerów rozruchu (work/r396-regression.sh, build r400z):
    14/14 przebiegów: wynik zgodny z zapisem r398q/r399 (work/r398q-regression.txt) poza zmianami
    zamierzonymi: menu z odliczaniem nie jest czytane przed klawiszem (GRUB z pakietu sam startuje
    wpis pierwszy po czasie - czytane komunikaty, menu po klawiszu); ekran Recovery Windows po
    odczytaniu tekstu dostaje też komunikat "Niebieski ekran śmierci" (od r399).
    Dodatkowo 4 przebiegi (GRUB, rEFInd, Windows, Limine) ze sterownikiem dźwięku r400:
    tekst mowy zgodny z przebiegami na sterowniku r389 (work/regression-r400-audio.out); sterownik otwarty, próbki dostarczone do karty (ślad "first PCM"). Dźwięk nagrany w próbie ISO (pkt 12).
